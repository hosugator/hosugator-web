## Context
실용주의 프로그래머 Topic 15를 읽으며 개발 파이프라인(비즈니스 목표 → 요구사항 → 모델 → 아키텍처 → 프로토타입 → 예광탄 → 반복 개발 → 배포 → 유지보수)을 정리하다, 이 폭포수 흐름과 애자일의 구조적 차이를 탐색함.

## Insight
### 애자일과 폭포수의 차이는 규모가 아니라 피드백 루프의 위치다

폭포수는 모든 단계를 순차적으로 완료한 후 배포에서 처음 사용자 피드백이 들어온다. 요구사항이 처음부터 틀렸을 경우 전체를 재작업해야 한다.

```
폭포수: 요구사항 → 설계 → 개발 → 테스트 → 배포 → [사용자 피드백]
애자일: [스프린트: 요구사항 일부 → 개발 → 테스트 → 배포] → [피드백] → [다음 스프린트]
```

### 이상적인 애자일에서 스프린트의 끝은 실제 배포를 의미한다

스프린트 종료 시 "배포 가능한 상태"를 유지하는 것이 최소 조건이고, 이상적으로는 실제 배포까지 수행한다. 배포 단위가 작아지므로 사용자 검증 시점이 빨라지고 각 배포의 리스크가 줄어든다. 배포까지의 거리와 단위를 줄이는 것이 핵심이지, 사용자 검증이 배포 후라는 구조 자체는 동일하다.

### 설계 단계는 초기 스프린트에 몰리고 이후 스프린트에서는 스킵된다

모델·아키텍처 설계는 매 스프린트마다 반복되지 않는다. 초기 스프린트에서 뼈대(예광탄)를 확립한 후, 이후 스프린트는 반복 개발 위주로 진행된다. 설계 검토는 스프린트의 기본 포함 항목이되, "변경 없음"이라는 판단 자체가 설계 검토의 결과다.
