## 워크플로우 제안 및 안내

영상의 방식을 적용하기 위해서는 깃허브 MCP 연결보다 로컬에 프로젝트를 클론하고 진행하는 방식을 더 추천합니다. 이 방식은 사용자가 에디터에서 직접 계획 문서를 수정하고 주석을 다는 인간 주도 루핑을 수행하기에 훨씬 수월하기 때문입니다.

### 단계별 진행 방법

- 리서치 단계: 프로젝트 루트 디렉토리에서 CLI를 실행하고 현재 코드베이스를 분석하여 주요 아키텍처와 로직을 요약한 research.md 파일을 생성해달라고 요청합니다. 이때 기술 스택인 FastAPI, Langchain, ChromaDB 등의 사용 방식을 중점적으로 분석하도록 지시하는 것이 좋습니다.
    
- 계획 단계: 생성된 리서치 파일을 기반으로 데모 기능을 추가하기 위한 상세 구현 계획을 plan.md 파일에 작성하라고 지시합니다. 영상의 조언처럼 변경될 파일 경로와 코드 스니펫이 포함되도록 요청하세요.
    
- 검토 및 수정 단계: 에디터에서 plan.md 파일을 열고 인라인 주석이나 메모를 직접 추가합니다. 예를 들어 특정 라이브러리 활용 방식을 지정하거나 예외 처리 로직에 대한 피드백을 남깁니다. 그 후 CLI에 메모를 반영하여 계획을 업데이트하고 아직 구현은 하지 마라는 명령을 내립니다.
    
- 구현 단계: 계획이 최종적으로 승인되면 plan.md에 기재된 모든 내용을 실제 코드로 구현하라는 명령을 내립니다. 이때 타입 체크를 지속적으로 수행하고 계획 문서에 완료 표시를 하도록 설정하면 좋습니다.
    

### 파일 관리 및 인식 방법

- 파일 위치: 모든 md 파일은 프로젝트의 루트 경로에 위치시키는 것이 가장 간단합니다. CLI는 보통 현재 작업 중인 디렉토리의 파일들을 컨텍스트로 읽어들일 수 있습니다.
    
- 명시적 참조: 명령을 내릴 때 plan.md 파일을 참고해서 작업해와 같이 파일명을 직접 언급하면 CLI가 해당 내용을 더 정확하게 파악합니다.
    
- 연속성 유지: 작업을 시작할 때 이전 세션에서 작성된 리서치 및 계획 문서를 먼저 읽게 함으로써 컨텍스트의 손실 없이 작업을 이어갈 수 있습니다.
