## Context
실용주의 프로그래머 Topic 15 추정 챕터에서 처음 만난 개념. "기본적인 것만 갖춘 개략적인 모델을 만들어 보라"는 조언에서 출발.

## Insight
### 추정 모델은 시스템을 컴포넌트로 분해하고 각 기여를 수식으로 연결한 것이다

어떤 수치(응답 시간, 소요 기간, 자원량 등)를 추정할 때, 시스템을 핵심 컴포넌트로 분해하고 그 관계를 수식으로 표현한다. 각 컴포넌트에는 전체 결과에 얼마나 기여하는지를 나타내는 매개변수가 붙는다.

**예시: API 응답 시간 추정**
```
응답 시간 = (요청 수 × 처리 시간) / 서버 수
```

컴포넌트: 요청 수, 처리 시간, 서버 수. 이 수식으로 "서버를 2배 늘리면 응답 시간이 절반"이라는 트레이드오프를 수식으로 비교할 수 있다.

### 모델을 만드는 과정 자체가 숨겨진 패턴을 드러낸다

정확한 수치를 얻는 것 외에도, 모델링 과정에서 이전에 보이지 않던 병목이나 가정이 드러나는 부수효과가 있다. 초기 질문이 재정의되는 경우도 많다.

### 모델의 정교함에는 수익 체감이 있다

두 배의 노력으로도 정확도는 미미하게 개선된다. 간결함과 정확성의 균형점은 경험으로 찾는다. 어느 수준에서 멈출지는 사전에 정할 수 없고 맥락에 따라 달라진다.
