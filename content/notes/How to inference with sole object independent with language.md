## Context
학습한 모델을 실제 현장에서 어떤 형태로 활용하게 되는지에 대해서 명확하게 대답할 수 없었다.

## Insight
### 학습은 Python이 사실상 표준이지만, 추론은 어떤 언어로도 가능하다.  

학습이 끝난 모델을 표준 포맷으로 내보내면(Export), Python이 없는 환경에서도 실행된다.
현업에서는 임베디드 수준의 하드웨어가 아닌 이상, 개발 환경을 추론 환경에 동일하게 이식한다. 그리고 모델만 추론 환경에 최적화된 런타임으로 교체하여 사용한다.

### 모델 객체는 프로세스 시작 시 1회만 RAM에 올라와 상주한다.  

사이클마다 같은 객체를 재사용하며, 추론 시 필요한 임시 버퍼만 생겼다 사라진다.

- **RAM**: 프로세스가 실행 중에 데이터를 읽고 쓰는 임시 저장 공간. 하드디스크보다 수백~수천 배 빠르지만 전원이 꺼지면 사라짐. 모델 가중치(수백 MB)가 올라가는 곳.
- **객체(Object)**: 가중치 행렬들과 추론 메서드를 묶은 데이터 구조체. `session = ort.InferenceSession("model.onnx")`의 `session`이 객체. RAM 어딘가에 주소를 갖고 상주한다.
- **임시 버퍼(Temporary Buffer)**: 추론 중에만 필요한 중간 계산 결과를 담는 메모리 영역. 입력 텐서, 각 레이어의 출력값이 여기 쌓였다가 추론이 끝나면 해제됨. 모델 가중치와 달리 사이클마다 새로 생겼다 사라진다.
- **스레드(Thread)**: 프로세스 안에서 독립적으로 실행되는 작업 단위. 여러 스레드가 동시에 실행되면 병렬 처리.

### 각 모델은 각자의 객체로 생성된다

하나의 객체가 여러 모델을 담는 것이 아니라, 모델마다 독립된 객체가 존재한다:

```python
session_m1  = ort.InferenceSession("m1.onnx")   # 객체 1, RAM 상주
session_m2a = ort.InferenceSession("m2a.onnx")  # 객체 2, RAM 상주
session_m3  = ort.InferenceSession("m3.onnx")   # 객체 3, RAM 상주
```

스레드가 같은 객체를 공유하고 입력 데이터 버퍼만 스레드별로 분리하는 방식(thread-safe inference)을 쓴다.  
ONNX Runtime이 이 방식을 기본 지원한다.

### 모델 가중치는 추론 중에 Read-only이다.

스레드별로 독립 분리되는 것은 입력 데이터와 중간 계산 버퍼뿐이다:

```
모델 객체 (가중치, read-only — RAM에 1개)
    ├── 스레드 1: [이미지 A 버퍼] → [임시 계산 버퍼 1] → [결과 A]
    ├── 스레드 2: [이미지 B 버퍼] → [임시 계산 버퍼 2] → [결과 B]
    └── 스레드 3: [이미지 C 버퍼] → [임시 계산 버퍼 3] → [결과 C]
```

하나의 스레드가 하나의 추론을 담당하는 것이 일반적인 패턴이다. 스레드 3개가 동시에 각기 다른 이미지를 추론하면, 가중치 1벌만 RAM에 올라간 채로 3개의 추론이 병렬로 진행된다.
