## Context
V1-AOI 조작 콘솔(PatchCore 기반) 구현 완료 보고에서 나온 성능 개선 사례. 최초 구현에서 추론 요청마다 6.5초가 걸렸다.

## Insight
### 6.5초 지연의 원인은 모델이 아니라 매 요청마다 새 프로세스를 띄운 것이었다

최초 구현은 추론 요청이 들어올 때마다 Python 프로세스를 새로 시작했다 — 모델 가중치 로딩·초기화 비용을 매 요청마다 반복 지불한 것.
모델을 메모리에 상주시켜 두고 요청만 라우팅하는 방식으로 바꾸자 요청당 0.4초로 줄었다(16배 개선). 
병목이 "모델 연산"이 아니라 "모델을 매번 다시 준비하는 과정"이었다는 것 — 추론 지연을 진단할 때 모델 자체의 속도와 모델을 준비하는 오버헤드를 분리해서 봐야 한다는 사례.

### 공개 벤치마크(MVTec) 통과는 파이프라인 검증이지 최종 성능 확정이 아니다

toothbrush 카테고리 기준 Image AUROC 0.914, Pixel AUROC 0.989로 기준치를 통과했지만, 이는 실제 렌즈 데이터가 아닌 MVTec 공개 데이터셋 기준이다.
"학습→평가→추론" 파이프라인 자체가 정상 동작한다는 것을 검증한 것이지, 실제 도메인(렌즈)에서의 성능을 보장하지 않는다 — 파이프라인 검증과 도메인 성능 검증은 별개 단계다.
