## Context
GF-88 커뮤니티 기능 FE-BE 연동 완료 후 "커뮤니티 게시글/댓글도 동기화 큐에 넣어야 하나?"라는 질문이 생겼다. GF-83에서 운동 기록에 대해서만 Bulk API + 멱등성 키 구조를 구현한 상태.

## Insight
### 오프라인 큐 적용 범위는 기능 수가 아니라 데이터 손실 리스크로 결정한다

모든 API 요청에 큐를 적용하면 복잡도만 늘어난다. 기준은 하나다: **오프라인 중 사용자가 데이터를 입력했을 때 손실이 큰가?**

| 기능 | 큐 필요 | 이유 |
|------|---------|------|
| 운동 기록 | ✅ | 헬스장 지하·등산 등 네트워크 불안정 환경에서 직접 입력. 손실 시 재현 불가 |
| 커뮤니티 게시글/댓글 | ❌ | 네트워크가 있을 때 작성하는 게 자연스러움. 실패 시 재작성 가능 |
| 하이파이브 | ❌ | 손실해도 큰 영향 없음 |
| 프로필/설정 | ❌ | 변경 빈도 낮고 명시적 액션 |

### 오프라인 큐 없는 기능은 서버 없이 동작하지 않는다

현재 커뮤니티는 서버 오프라인 시 API 실패 → 에러 표시. 이건 의도된 동작이다. Instagram도 오프라인 포스팅을 지원하지 않는다.

## Decision
운동 기록에만 오프라인 큐(Bulk API + 멱등성 키) 적용을 유지한다. 커뮤니티는 서버 필수 API로 유지.
**전환 조건:** 커뮤니티 사용 중 네트워크 단절로 인한 데이터 손실 리포트가 실제로 발생하면 재검토.
