## 클로드 코드를 활용한 실전 워크플로우 정리
### 워크플로우
- 리서치: research.md에 전체 자료를 상세 분석한 내용을 영구적인 결과물로 남긴다.
- 계획: plan.md에서 research.md로 파악한 구조와 맥락 하에서 사용자가 원하는 지시에 맞게 계획을 수립한다.
- 주석(반복): plan.md를 사용자가 직접 살펴보고 방향성을 조절한다. 이 때, 코드 구현은 명시적으로 수행하지 못 하도록 한다.
- 구현: 코드 레벨에서 감독관의 역할로 변경하여 계획대로의 구현에 집중한다. 
- 피드백: 잘못 구현된 부분은 구현 이전으로 롤백하여 다시 작업을 진행함이 원칙이다.

## 리서치
가장 무서운 실패를 방지하기 위한 구조와 맥락 이해 파일이다.
가장 무서운 실패란 그 자체로는 동작하지만 주변에 악영향을 미치는 코드이다.
- 기존 레이어를 무시하는 함수
- ORM 관례를 무시하는 마이그레이션
- 중복된 API 엔드포인트
### 프롬프트 예시
- 이 폴더를 자세히 읽고, 어떻게 동작하는지 깊이 이해하고, 모든 세부사항을 파악해라. 끝나면 reserach.md에 상세보고서를 작성해라.
- 알림 시스템을 상세히 연구하고, 알림이 어떻게 작동하는지 모든 것을 담은 research.md를 작성해라.
## 계획
### 내용
- 접근방식 상세설명
- 코드 스니펫
- 파일 경로
- 트레이드오프
### 프롬프트 예시
- 새 기능 ETF 리밸런싱을 구현하는 상세 plan.md를 작성해라. 코드 스니펫도 포함해라.
- 오프셋 페이징 대신 인풋 페이징을 지원해야 한다. 이를 위한 상세 plan.md를 작성해라. 소스 파일을 읽고 실제 코드베이스를 기반으로 계획을 작성해.
## 주석

- 가정 수정
- 접근방식 거부
- 제약조건 추가
- 도메인지식 삽입

## 구현
이 시점에서는 모든 계획이 검증된 상태이다. 
사용자의 역할은 설계자에서 감독자로 변경된다.
구현은 기계적이어야 한다.
세션마다 재사용하는 표준 프롬프트를 사용한다.
### 프롬프트 예시
전부 구현해라.
작업 단계별로 계획 문서에 완료로 표시해라.
모든 작업 단계가 완료될 때까지 멈추지 마라.
any나 unknow 타입을 사용하지 마라.
지속적으로 type check를 해서 새로운 문제를 예방해라.
