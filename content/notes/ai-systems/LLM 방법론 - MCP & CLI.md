- MCP와 CLI는 LLM의 외부 앱 사용을 위한 방법론이다.
- MCP
	- MCP는 LLM을 위한 API이다.
	- JSON-RPC로 쓰였으며, 정해진 명령어(`list_tools`)를 통해 LLM이 정의된 MCP의 기능들과 주석을 보고 사용한다.
	- MCP 개발자가 정의해둔 기능만을 사용할 수 있으나, 그만큼 LLM의 작업이 결정성을 갖는다.
	- 그러나 MCP의 정해진 명령어들을 모두 맥락으로 들고 사용하므로 토큰 소모량이 많다.
	- MCP는 인터페이스(CLI/GUI)에 종속된 기술이 아니라, '모델(LLM)'을 위한 규격이므로 앱, IDE에서도 사용 가능하다.
- CLI
	- 사전적 의미의 Command Line Interface를 넘어서, LLM이 쉘 권한을 갖는 방법론을 의미한다.
	- 이 방식은 MCP처럼 특정 기능을 주는 것이 아니라, 시스템 전체를 다룰 수 있는 권한이기에 소스 코드를 직접 고쳐서 기능을 만드는 것과 유사하다.
	- 다시 말해, LLM이 이미 완벽히 이해하고 있는 터미널 명령어를 사용하여 외부 프로그램을 조작하는 코드를 직접 만들어낸다.
	- 그러나 auth 관련해서는 사용하려는 외부 앱의 CLI 도구가 있거나, 사용자의 인증이 필요하다.
	- 또한, 원시적인 터미널 명령어들을 사용해서 기능을 직접 개발하기에 에러의 위험이 존재한다.
	- LLM의 한계인 환각, 비결정성(동일한 자연어 명령어라도 다른 결과가 도출)의 위험이 존재한다.
