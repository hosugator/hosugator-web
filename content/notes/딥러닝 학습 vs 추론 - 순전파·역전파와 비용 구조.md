## 핵심 원칙

학습이 추론보다 느린 이유는 단순히 "여러 번 반복"이기 때문만이 아니다.  
1회 학습 자체가 1회 추론보다 연산량·메모리 사용량이 훨씬 크다.

---

## 추론 vs 학습의 1회 비용 차이

### 추론 (Inference): 순전파만

```
입력 → Layer1 → Layer2 → ... → LayerN → 출력(예측)
  ↑                                          ↑
데이터 흐름이 한 방향                    끝. 결과만 반환.
```

- 각 레이어의 중간 결과는 다음 레이어로 넘긴 뒤 버려도 된다.
- 연산: 순전파 1회

### 학습 (Training): 순전파 + 역전파

```
[순전파]
  입력 → Layer1 → Layer2 → ... → LayerN → 출력
                                              ↓
                                        오차(Loss) 계산
                                         "얼마나 틀렸나"
[역전파]
  출력 ← LayerN ← ... ← Layer2 ← Layer1
    ↑
  오차를 거꾸로 흘려보내며
  각 레이어의 가중치 기울기(gradient) 계산
    ↓
  가중치 업데이트 (gradient descent)
```

역전파는 순전파와 같은 경로를 거꾸로 통과한다. 연산량이 순전파의 약 2배다.

<!-- 💡 "역전파"라는 이름 그대로다. 오차 신호가 출력에서 입력 방향으로 역방향 전파된다. -->

---

## 왜 역전파에 순전파 결과가 필요한가

역전파 시 Layer2의 기울기를 구하려면 Layer1의 출력값이 필요하다.  
(미분의 연쇄 법칙 — chain rule)

```
Layer2의 기울기 = f(Layer1의 출력, 현재 가중치, 오차)
                          ↑
              순전파 때 계산해둔 값
```

따라서 학습 중에는 모든 레이어의 중간 출력값을 전부 메모리에 보관해야 한다.

```
추론:  Layer1 계산 → 결과 전달 → Layer1 중간값 버림   ← 메모리 절약
학습:  Layer1 계산 → 결과 전달 → Layer1 중간값 보관   ← 메모리 급증
                                        ↑
                          역전파 때까지 살아있어야 함
```

이것이 학습 시 GPU 메모리가 추론 대비 수배 더 필요한 이유다.  
배치 크기를 키울수록 보관해야 할 중간값이 늘어나 더 큰 GPU 메모리가 필요해진다.

## 수렴까지 반복 — 학습 시간이 긴 진짜 이유

```
1 epoch = 전체 데이터셋을 1회 순전파+역전파
학습 = 수십~수백 epoch 반복

예시:
  ImageNet 데이터셋: 128만 장
  배치 크기: 256장
  1 epoch = 5,000 step (순전파+역전파 5,000회)
  학습: 90 epoch = 450,000 step
```

한 step의 비용(순전파 × 3)이 크고, 그것을 수십만 번 반복하므로 총 시간이 매우 길어진다.

## 파라미터 수와 GPU 필요성

딥러닝은 레이어가 많다 = 행렬이 많다 = 행렬 곱셈이 많다.

```
ResNet-50:  2,500만 개 파라미터
GPT-3:      1,750억 개 파라미터
```

파라미터가 많다는 것은 곧 행렬 곱셈의 규모가 크다는 뜻이다.  
행렬 곱셈은 각 원소가 독립적이어서 병렬 처리에 최적이고,  
GPU는 이 병렬 처리를 수천 코어로 한번에 처리한다.

→ 파라미터가 많을수록 학습·추론 양쪽 모두 GPU 없이는 현실적으로 불가능해진다.

<!-- 💡 추론도 GPU가 필요한 경우가 많다. GPT-3 추론 한 번에도 1,750억개의 파라미터를 통과해야 하므로, 실시간 서비스라면 CPU로는 응답 속도를 맞출 수 없다. -->

## 학습/추론 비용 비교 요약

| 항목      | 추론       | 학습                |
| ------- | -------- | ----------------- |
| 연산 방향   | 순전파 1회   | 순전파 + 역전파 (≈ 3배)  |
| 중간값 보관  | 불필요 (버림) | 필수 (역전파용)         |
| GPU 메모리 | 적음       | 많음 (배치 × 레이어 수만큼) |
| 반복 횟수   | 1회       | 수십만 step          |
| 총 시간    | 짧음       | 매우 김              |

## Coreset 거리 계산 — 순서 의존 vs 레이어 내 병렬의 실제 사례

PatchCore의 Coreset Greedy Sampling은 학습/추론과 다른 형태의 병렬성 문제다.

```
스텝 간:  스텝 n+1은 n의 결과(선택된 점)를 알아야 함 → 직렬 불가피
스텝 내:  나머지 25,000개 벡터까지의 거리 계산은 서로 독립 → 병렬 가능

거리 계산 = 두 벡터(1,536차원)의 유클리드 거리
  d = √( (a₁-b₁)² + (a₂-b₂)² + ... + (a₁₅₃₆-b₁₅₃₆)² )
  → 1,536번의 빼기·제곱·덧셈

GPU가 빠른 이유:
  25,000개 벡터의 거리를 각각 다른 코어가 동시에 계산
  CPU는 24코어라 1,042번 묶어서 순서대로 처리
```

→ [[병렬 처리 - CPU와 GPU의 코어 구조 차이]] 에서 다룬 "독립 연산 = 병렬 가능" 원칙이 그대로 적용된다.
