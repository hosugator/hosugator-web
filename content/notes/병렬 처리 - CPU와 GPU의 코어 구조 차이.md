## 핵심 원칙

CPU와 GPU의 차이는 "빠르냐 느리냐"가 아니라 "어떤 종류의 일에 최적화됐냐"다.  
CPU는 복잡한 일 하나를 빠르게, GPU는 단순한 일 수천 개를 동시에.

---

## 코어 구조 비교

```
CPU (Intel i9 기준):
  코어 24개
  각 코어: 복잡한 연산, 분기 예측, 캐시 관리에 특화
  → 복잡한 로직 하나를 매우 빠르게

GPU (NVIDIA A100 기준):
  코어 6,912개
  각 코어: 단순 연산(곱셈, 덧셈)에 특화, 제어 회로 최소화
  → 단순한 연산을 수천 개 동시에
```

> 직관: CPU는 숙련된 요리사 24명, GPU는 단순 작업을 하는 공장 라인 6,912개.  
> 복잡한 레시피는 CPU가 낫고, 단순한 재료 손질은 GPU가 압도적이다.

## 병렬 처리가 가능한 조건

모든 연산이 GPU에서 빠른 건 아니다. 각 작업이 서로 독립적일 때만 병렬화가 가능하다.

```
병렬화 가능 (독립):
  작업 A, B, C가 서로의 결과를 필요로 하지 않음
  → A, B, C를 동시에 실행

병렬화 불가 (순서 의존):
  작업 B는 A의 결과가 필요
  → A 완료 후 B 시작, 직렬 실행 불가피
```

<!-- 💡 딥러닝에서 레이어 간 계산은 직렬(앞 레이어 결과가 필요), 레이어 내 행렬 곱셈은 병렬(각 원소가 독립). 이 두 층위를 구분하는 것이 중요하다. -->

## 행렬 곱셈이 GPU에 최적인 이유

딥러닝의 핵심 연산은 행렬 곱셈이다.

```
출력 = 입력 (1 × 1,536)  ×  가중치 (1,536 × 1,536)

출력의 각 원소:
  출력[0] = 입력[0]×가중치[0,0] + 입력[1]×가중치[1,0] + ... (1,536번 연산)
  출력[1] = 입력[0]×가중치[0,1] + 입력[1]×가중치[1,1] + ... (1,536번 연산)
  ...
  출력[1535] = ...

출력[0]과 출력[1]은 서로 독립 → 동시에 계산 가능
```

1,536개의 출력 원소를 GPU 코어 1,536개가 동시에 담당하면 이론적으로 1,536배 빠르다.

## SIMD — CPU도 병렬 처리를 한다

CPU도 SIMD(Single Instruction, Multiple Data) 명령어로 병렬 처리가 가능하다.

```
일반 덧셈:  a[0]+b[0], a[1]+b[1], a[2]+b[2], a[3]+b[3]  → 4번 순서대로
AVX-512:    a[0..15]+b[0..15]  → 16개를 한 명령어로 동시 처리
```

PyTorch는 CPU 연산 시 MKL(Intel Math Kernel Library) 또는 OpenBLAS를 통해  
모든 코어의 SIMD를 자동으로 활용한다.

```
GPU: 수천 코어 × SIMD → 수만 병렬
CPU: 수십 코어  × SIMD → 수백 병렬
```

규모 차이가 있을 뿐 원리는 동일하다. 배치 크기가 크고 독립적인 연산이라면  
CPU도 모든 자원을 활용한다.

## 어떤 경우에 GPU가 결정적으로 유리한가

| 상황 | CPU | GPU |
|------|-----|-----|
| 대형 행렬 곱셈 (딥러닝) | 수십 병렬 | 수만 병렬 — 압도적 |
| 소형 행렬 (레이어 1~2개) | 오버헤드 적어 경쟁력 있음 | dispatch 오버헤드로 오히려 느릴 수도 |
| 순서 의존 로직 (if/else, 재귀) | 유리 | 불리 (코어가 단순 연산 특화) |
| 대규모 독립 데이터 처리 | 불리 | 유리 |
