## 경량 분류 모델 — MobileNet vs EfficientNet

두 모델 모두 "가벼운 분류"를 목표로 하지만 접근 철학이 다르다.

### MobileNet — 극한의 경량화
Depthwise Separable Convolution으로 연산량을 약 1/9 수준으로 줄인다.

```
일반 Conv: 공간 + 채널 동시 처리 → 표현력 높음, 연산 많음
Depthwise: 채널별 독립 공간 처리 (연산 감소)
Pointwise: 1×1 Conv로 채널 통합
→ 정확도 일부 손실, 크기 극단적 감소 (~4MB)
```

**채널(Channel)이란:**  
입력 이미지에서 채널 = R/G/B 3개. 맞다.  
그러나 CNN 중간 레이어로 가면 채널이 64 → 128 → 256개로 증가한다. 이 때 각 채널은 "특정 패턴 감지기"에 해당한다 (엣지 감지기, 질감 감지기 등).

일반 Conv가 비싼 이유는 **공간 탐색(3×3)과 채널 혼합을 동시에** 수행하기 때문이다.  
채널이 256개인 레이어에서 필터 하나의 크기 = `3×3×256 = 2,304개` 파라미터.

- **공간 탐색(Spatial Filtering)**: 커널이 이미지 위를 슬라이딩하며 **주변 픽셀들의 패턴**을 찾는 작업. "이 위치 주변에 엣지가 있는가? 특정 질감이 있는가?" — 위치 간 관계를 포착한다.
- **채널 혼합(Channel Mixing)**: 여러 채널(패턴 감지기들)의 정보를 **결합**하여 더 복합적인 특징을 만드는 작업. "엣지 감지기 + 색상 감지기를 합쳐 붉은 엣지를 감지"하는 식 — 채널 간 관계를 포착한다.

Depthwise가 연산을 줄이는 원리는 이 두 작업을 **분리**하는 것이다:

```
[일반 Conv]
공간 탐색(3×3) + 채널 혼합(256개) → 동시 처리
비용: H×W × C_in × C_out × 9

[Depthwise Separable Conv]
① Depthwise: 채널별 독립 공간 탐색(3×3) — 채널 간 교류 없음
   비용: H×W × C_in × 9
② Pointwise: 1×1로 채널 혼합만 수행
   비용: H×W × C_in × C_out

합산 비용 / 일반 Conv 비용 ≈ 1/C_out + 1/9 ≈ 1/9  (채널이 충분히 많을 때)
```

핵심: 3개 채널을 독립 처리해서 줄이는 게 아니라, 256채널 혼합 비용을 "공간 탐색이 끝난 뒤"로 분리함으로써 중복 계산을 제거하는 것이다.

**커널(Kernel)이란:**  
이미지 위를 슬라이딩하는 작은 가중치 행렬. 필터(Filter)라고도 부른다.  
3×3 커널 = 9개의 숫자로 이뤄진 배열. 이미지의 각 위치에 겹쳐 내적(element-wise 곱의 합)을 계산하고, 그 결과값 하나를 출력한다.

```
이미지 패치    커널(3×3)     출력값 1개
[1 2 3]      [a b c]
[4 5 6]  ×   [d e f]  →   합산 스칼라값
[7 8 9]      [g h i]
```

이 과정을 이미지 전체 위치에서 반복하면 특징 맵(Feature Map) 1장이 생성된다.

**1×1 Conv란:**  
커널 크기가 1×1 — 즉, 주변 픽셀을 전혀 참조하지 않는다. 각 위치에서 채널들 간의 선형 조합만 수행한다.  
일반 Conv(3×3, 5×5 등)가 "공간에서 패턴을 찾는 것"이라면, 1×1 Conv는 "채널들을 섞는 믹서"다.  
역할: 채널 수 조절(256→64 압축 또는 확장), Depthwise가 분리해 둔 채널 정보를 뒤늦게 통합.

적합 상황: MCU, 모바일, 초저사양 엣지. 단순 Pass/Fail 이진 분류.

### EfficientNet — 정확도와 크기의 균형
Compound Scaling: 모델을 키울 때 깊이·너비·해상도를 수학적 비율로 동시 확장.

| 차원 | 정의 | 역할 | 한계 |
|------|------|------|------|
| **깊이(Depth)** | 레이어 수 | 더 복잡한 추상 특징 학습 | 너무 깊으면 기울기 소실 |
| **너비(Width)** | 레이어당 채널 수 | 더 다양한 패턴 감지기 확보 | 너무 넓으면 파라미터 폭발 |
| **해상도(Resolution)** | 입력 이미지 크기 | 세밀한 디테일 포착 | 크기 제곱에 비례해 연산량 증가 |

세 차원 중 하나만 키우면 나머지가 병목이 된다. EfficientNet은 논문에서 도출한 최적 비율(compound coefficient φ)로 셋을 동시에 확장한다.

```
기존: 레이어만 쌓는다 → 수확 체감 (Diminishing Returns)
EfficientNet: 세 차원을 균형있게 동시 확장 → 효율적 성능 향상
B0(최소) ~ B7(최대)로 연속적 스케일 조정 가능
```

**수확 체감(Diminishing Returns):** 레이어를 계속 쌓을수록 성능 향상 폭이 점점 줄어드는 현상.

```
10레이어 추가 → +5% 성능
10레이어 추가 → +2%
10레이어 추가 → +0.3%
10레이어 추가 → 오히려 저하 (기울기 소실, 과적합)
```

한 방향(깊이)만 키우면 다른 병목(너비 좁음, 해상도 낮음)이 드러나기 때문이다.  
EfficientNet은 깊이·너비·해상도를 동시에 균형 있게 키워 이 병목을 회피한다.

적합 상황: GPU 없는 엣지 서버, 결함 유형 분류기. MVTec 기준 B4가 산업 검사 기본 베이스라인.

## ViT (Vision Transformer) — 이미지를 문장처럼 읽는다

이미지를 16×16 패치로 분할 → NLP 토큰처럼 취급 → Self-Attention으로 전역 관계 학습.

```
CNN: 주변 픽셀만 본다 (局所, local receptive field)
ViT: 이미지 전체를 동시에 본다 (全域, global attention)
```

임계 조건: 데이터가 클래스당 2,000장 이상일 때 CNN을 앞선다. 소량 데이터에서는 EfficientNet에 밀린다. ImageNet 사전학습(ViT-B/16)이 있어도 fine-tuning에 많은 데이터 필요.

## 객체 검출 — YOLO vs DETR

### YOLO — 앵커 기반, 빠름
격자마다 미리 설정한 앵커 박스를 조정. 후처리(NMS)로 중복 제거.
앵커 크기를 데이터에 맞게 사전 설계해야 한다.

### DETR — 앵커 없음, 우아함
Transformer Encoder-Decoder + N개의 Object Query가 각각 객체를 직접 예측.  
앵커 설계·NMS 후처리 불필요. 하지만 수렴이 매우 느리다 (YOLO 대비 10배+ epoch).

RT-DETR: DETR의 느린 수렴 문제를 개선, 실시간 추론 가능. 소형 결함 탐지에서 YOLO보다 우수.

| | YOLO | RT-DETR |
|--|------|---------|
| 앵커 | 필요 | 불필요 |
| 학습 | 빠름 | 느림 |
| 소형 객체 | 약점 | 강점 |
| 라이선스 | AGPL-3.0 ⚠️ | Apache 2.0 |

> ⚠️ YOLOv8 AGPL-3.0: 상용 배포 시 소스코드 공개 의무. 내부 프로토타입은 무관하나 상용화 단계에서 재검토 필요.
