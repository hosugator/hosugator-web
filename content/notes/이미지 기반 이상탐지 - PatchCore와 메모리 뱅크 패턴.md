## 핵심 전제
이미지 기반 이상탐지 모델들은 방식은 달라도 공통 전제를 공유한다:  "정상이 어떻게 생겼는지를 외운 뒤, 다르게 생긴 것을 이상으로 판단한다."
불량 이미지가 없어도 작동한다는 점에서 라벨 데이터 수집이 어려운 제조업에 구조적으로 적합하다.

## Feature Embedding — 모든 방식의 공통 기반
ImageNet(대규모 공개 데이터셋)으로 사전학습된 CNN(Convolutional Neural Network) 기반 모델을 백본으로 특징 추출용으로 사용한다.  
가중치는 고정(frozen)으로 렌즈/제품 이미지로 별도 학습 불필요하다.
별도 학습 없는 추론이 가능한 이유는 CNN이 이미지라는 데이터의 구조 자체를 학습했기 때문이다. (픽셀 배열을 받아 "가장자리 → 질감 → 형태 → 물체" 순으로 계층적 패턴을 학습)
또한 사전 학습된 모델(ResNet)의 최종 분류 레이어를 떼어내고, 중간 레이어의 출력(Feature 벡터)만 꺼내어 사용한다.
다시 말해, ResNet을 "이미지를 숫자 배열로 압축하는 변환기"로만 활용한다.

```
이미지 픽셀 → [Pre-trained ResNet] → Feature 벡터 (512차원)
```


## 방식별 비교
### 1. 메모리 뱅크 (PatchCore, PaDiM) + KNN(K-Nearest Neighbors) + Coreset(Greedy Subsampling)

이미지를 격자 패치로 분할 → 패치별 Feature를 메모리 뱅크에 저장.  
추론 시 KNN 거리로 정상/이상 판정.

KNN과 메모리 뱅크의 역할 구분:

- KNN (K-Nearest Neighbors): 새로운 벡터가 들어왔을 때, 저장된 벡터들 중 가장 가까운 K개를 찾아 거리를 계산하는 알고리즘. 학습이 없고 순수하게 거리 비교만 한다.
- 메모리 뱅크: 정상 패치의 Feature 벡터를 담아두는 저장소(데이터베이스). 계산 로직은 포함하지 않는다.
- 둘의 관계: 메모리 뱅크는 "비교 기준 데이터", KNN은 "비교하는 방법". 추론 시 KNN이 메모리 뱅크를 조회하여 거리를 계산한다.

```
[학습]
정상 이미지 N장 → 패치 Feature 수십만 개
    ↓ Coreset: 전체 분포를 대표하는 10%만 선별 (Greedy 방식)
메모리 뱅크 = 대표 벡터 집합 (이미지 수에 무관하게 수렴)

[추론]
신규 이미지 → 패치 Feature → 뱅크와 거리 계산
거리 멀다 → 이상
```

Coreset의 역할: 이미지가 아무리 추가되어도 뱅크 크기가 발산하지 않도록 대표 벡터만 유지. 1,000장 추가해도 뱅크는 ~1,000개 벡터 수준에서 수렴. 

Coreset 선정 방식 (Greedy Subsampling): 평균값/중간값이 아니다. 탐욕적 최대 거리 알고리즘을 사용한다.
1. 임의의 벡터 1개를 선택
2. 이미 선택된 벡터들과의 최소 거리가 가장 큰 벡터를 다음으로 선택
3. 목표 개수에 도달할 때까지 반복

결과적으로 선택된 벡터들이 전체 분포 공간을 고르게 커버한다. 밀집 구간에서 중복 벡터를 걸러내고, 드문 패턴도 누락하지 않는 방식.

재학습 특성: 가중치 업데이트 없음. 메모리 뱅크 재구성 = 재학습. CPU, 수 분 완료. CI/CD 자동화에 가장 적합.

메모리 뱅크 자체에는 학습 파라미터가 전혀 없다 — 단순 벡터 저장소다. 
따라서 "재학습"이란 메모리 뱅크를 새 정상 이미지로 재구성하는 것이며, 역전파(backpropagation)가 일어나지 않는다. 
GPU가 필요 없는 이유가 이것이다.

### 2. Knowledge Distillation (EfficientAD)

Teacher(대형, frozen) → Student(소형, 학습대상) 구조.  
Student는 정상 이미지만 보고 Teacher를 모방하도록 학습됨.  
불량 이미지 입력 시 Teacher와 Student의 출력 차이(Gap)가 이상 점수.

- 장점: 모델이 작아 엣지 배포(OpenVINO 최적화) 최적
- 단점: 재학습 시 GPU + 수 시간 필요

### 3. Normalizing Flow (FastFlow)

정상 Feature 분포를 정규분포로 변환하는 함수(Flow)를 학습.  
추론 시 변환 후 정규분포 안/밖으로 정상/이상 판정.  
픽셀 단위 이상 맵(Anomaly Map) 출력에 강점.

## MVTec 벤치마크 기준 성능 비교

| 모델          | 방식               | Image AUROC | 최소 이미지   | GPU 학습 |
| ----------- | ---------------- | ----------- | -------- | ------ |
| PatchCore   | 메모리 뱅크           | ~99%        | 100~300장 | 불필요    |
| PaDiM       | 메모리 뱅크           | ~97%        | 200~300장 | 불필요    |

| FastFlow    | Normalizing Flow | ~99%        | 300~500장 | 필요     |

## PatchCore의 도메인 갭 상쇄 원리
PatchCore는 ImageNet 백본을 일관된 변환 함수 f(x)로 사용한다.  
메모리 뱅크 구성과 추론이 동일한 f(x)를 통과하므로 두 항이 같은 편향을 갖는다.

```
메모리 뱅크 구성: f(정상 이미지)  → 기준 벡터 집합
추론:             f(신규 이미지)  → 비교 벡터
                        ↑ 같은 f(x)
```

비교 연산은 절대값이 아닌 상대적 거리를 기준으로 하므로, 편향이 상쇄된다.  
즉, ResNet이 ImageNet 조명으로 학습되었어도 문제가 되지 않는다.

성립 조건: 메모리 뱅크 구성 시 조명 = 추론 시 조명.  
조명이 달라지면 f(x)의 출력 분포 자체가 이동하여 거리 기준이 무너진다.

## 프록시 데이터 검증 패턴

실제 검사 대상 이미지가 없을 때 MVTec AD의 유사 카테고리(texture류: leather, tile)로 파이프라인을 먼저 검증한다. 데이터 경로만 교체하면 동일 파이프라인으로 실제 데이터 전환 가능.

> MVTec AD: 독일 MVTec사 공개 산업 이상탐지 벤치마크. 15개 카테고리, 정상+불량+픽셀 마스크 포함.

## PatchCore의 비용 비대칭성

학습과 추론의 비용 구조가 반대 방향으로 비대칭하다.

| 관점 | 비용 | 이유 |
|------|------|------|
| 학습 | 경량 | 역전파 없음. 정상 이미지를 1회 통과 후 뱅크 저장으로 끝 |
| 추론 | 중량 | 신규 벡터 vs 메모리 뱅크 전체 거리 계산 (뱅크 크기에 비례) |

Coreset으로 뱅크를 10%로 압축하는 것이 추론 비용 완화의 핵심 장치다.

## 레이어 선택의 정확한 의미

`layers: ["layer2", "layer3"]` 설정은 layer2, layer3만 계산한다는 뜻이 아니다.

```
입력 → layer1(계산) → layer2(계산, 출력 저장★) → layer3(계산, 출력 저장★) → 중단
```

- layer1~3은 모두 계산에 참여한다. layer2의 입력이 layer1의 출력이므로 건너뛸 수 없다.
- layer4 이후는 실행 자체를 하지 않아 계산을 아낀다.
- layer1 출력을 저장하지 않는 이유: 엣지·밝기 등 모든 이미지에 공통으로 존재하는 저수준 정보라 정상/이상 판별력이 낮다.

두 레이어 출력의 결합 방식은 **concatenation(이어붙이기)**이다. 같은 패치 위치에서 나온 두 벡터를 순서대로 붙여 단일 벡터로 만든다.

```
layer2 출력: 512차원
layer3 출력: 1024차원
결합 후:    1536차원 (단일 벡터)
```

FK나 조인 없이 바로 거리 계산이 가능한 이유: 추론 시에도 동일한 결합 과정을 거치므로 구조가 항상 동일하다.

## 패치 단위 저장의 이유

이미지 단위로 평균해서 저장하면 안 되는 이유가 두 가지다.

**1. Anomaly Map 생성 불가**: 패치 위치 정보가 없으면 "어느 좌표가 이상한가"를 역추적할 수 없다.

**2. 이상 패치 희석**: 스크래치가 차지하는 패치는 1024개 중 수 개에 불과하다. 평균을 내면 정상 패치 1000개에 묻혀 오판한다.

```
정상 패치 1020개 × 거리 0.02 + 이상 패치 4개 × 거리 0.90
이미지 평균: 0.023 → 정상으로 오판
패치 최댓값: 0.90  → 이상 탐지
```

PatchCore가 이미지 Anomaly Score를 패치 거리의 **최댓값**으로 정의하는 이유가 이것이다.

## Anomaly Map의 색상 해석 주의점

현재 일반적 구현은 **이미지 내 상대 min-max 정규화**를 사용한다.

```python
norm = (anomaly_map - a_min) / (a_max - a_min) * 255
# 이 이미지 안의 최솟값→0, 최댓값→255(빨강)으로 강제
```

결과적으로 정상 이미지에도 반드시 붉은 영역이 생긴다. "이 이미지 안에서 상대적으로 가장 의심스러운 곳"을 표시할 뿐, 절대적 이상 판정이 아니다.
**절대 판정 기준**: Anomaly Score(이미지 레벨 스칼라). 학습 후 산출된 임계값(threshold)을 초과하는지로 정상/불량을 결정한다.

## 알고리즘 vs 모델 구분

두 용어는 혼용되지만 구분 기준이 있다.

| 구분 | 정의 | 예시 |
|------|------|------|
| 알고리즘 | 문제를 푸는 절차. 데이터와 무관하게 존재 | PatchCore 방법론 |
| 모델 | 알고리즘을 특정 데이터에 적용한 결과물. 파일로 저장 가능 | `epoch=0-step=83.ckpt` |

```
PatchCore 알고리즘 + leather 데이터 → PatchCore 모델(.ckpt)
     절차                재료              결과물
```
