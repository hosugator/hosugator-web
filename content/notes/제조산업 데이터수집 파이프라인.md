### 1. 제조 산업에서의 인터넷 표준 기술

과거의 공장 기계들은 제조사마다 제각각인 폐쇄적인 통신 프로토콜(전용 규격)을 사용했습니다. 하지만 최근에는 범용적으로 쓰이는 **인터넷 기술(TCP/IP 기반)**을 도입하여 서로 다른 장비 간에도 데이터를 쉽게 주고받을 수 있게 되었습니다.

- **HTTP/HTTPS**: 웹 브라우저에서 쓰는 그 방식입니다. 주로 대시보드 형태의 모니터링이나 클라우드 서버로 데이터를 전송할 때 사용합니다.
- **MQTT (Message Queuing Telemetry Transport)**: 지연 시간이 낮고 전력 소모가 적어 **IIoT**에서 가장 많이 쓰이는 '발행-구독(Publish-Subscribe)' 방식의 표준 프로토콜입니다.
  - *IIoT(Industrial IoT)란?* IoT(스마트홈·웨어러블 등 일반 소비자 기기 연결)의 산업 현장 버전입니다. 공장·발전소·물류 설비를 인터넷에 연결하는 것으로, 소비자 IoT보다 높은 신뢰성·실시간성·보안이 요구됩니다.
- **OPC-UA (Open Platform Communications Unified Architecture)**: 산업용 장비 간의 상호 운용성을 위해 만든 표준입니다. 기계의 데이터를 일관된 형식으로 변환해 주어 MES나 ERP와 연결하기 좋게 만듭니다.
- **RESTful API**: 서로 다른 **소프트웨어 시스템**(예: MES와 ERP) 간에 데이터를 주고받을 때 사용하는 표준 인터페이스 방식입니다.

#### MQTT / OPC-UA / REST는 대체재인가, 보완재인가?

**보완재**입니다. 사용 목적과 계층이 다릅니다.

| 프로토콜 | 주요 사용 계층 | 특징 |
|---|---|---|
| **MQTT** | L1 → L3 | 실시간 센서 데이터 스트리밍. 소량 메시지를 고속·저전력으로 전송 |
| **OPC-UA** | L1 → L3 | 이기종 장비 간 데이터 구조 표준화. "무슨 값인지" 의미까지 함께 전달 |
| **REST API** | L3 ↔ L5 | 비즈니스 시스템(MES-ERP, 클라우드) 간 요청-응답 연동 |

#### MES / WMS / ERP 구분

세 시스템 모두 **소프트웨어**이며, 관리 범위가 다릅니다.

| 시스템 | 전체 명칭 | 관리 범위 | 비유 |
|---|---|---|---|
| **ERP** | Enterprise Resource Planning | 전사 자원 (회계·인사·구매·재고) | 회사 전체 살림 관리 |
| **MES** | Manufacturing Execution System | 공장 내 생산 실행 (작업 지시·품질·실적) | 공장 생산 관리 |
| **WMS** | Warehouse Management System | 물류 창고 입출고·보관·피킹 | 창고 물류 관리 |

**장비 간 vs 소프트웨어 간 통신의 차이**: 장비 간은 PLC ↔ SCADA처럼 하드웨어 기기들이 신호를 주고받는 것이고, 소프트웨어 간은 MES ↔ ERP처럼 서버 프로그램들이 데이터를 교환하는 것입니다. 하위 계층(L0~L2)에서는 장비 간 통신이 지배적이고, 상위 계층(L3~L5)으로 올라갈수록 소프트웨어 간 통신이 주를 이룹니다.

### 2. 제조 산업 데이터 수집 계층 구조 (Purdue Model 기반)

**퍼듀 모델(Purdue Model)**이란 1990년대 퍼듀 대학교에서 제안한 산업 제어 시스템(ICS) 네트워크 참조 모델입니다. 공장 시스템을 0~5계층으로 나누어 각 계층의 기능과 보안 경계를 정의하며, 현재도 OT/IT 보안 설계의 표준 참조 모델로 널리 쓰입니다.

| **계층 (Level)**  | **명칭**                  | **주요 장치 및 기능**         | **데이터 흐름 특징**                |
| --------------- | ----------------------- | ---------------------- | ---------------------------- |
| **Level 4 & 5** | **Enterprise / Cloud**  | ERP, SCM, 클라우드 서버      | 전사적 경영 데이터 및 장기 분석 데이터 관리    |
| **Level 3**     | **Operations (MES)**    | MES, 품질 관리(QMS), 서버    | 공장 전체의 실행 계획 및 공정 데이터 집계     |
| **Level 2**     | **Control (SCADA/HMI)** | SCADA, HMI, 로컬 서버      | 공정 감시 및 제어, 현장 데이터 가시화       |
| **Level 1**     | **Control Devices**     | **PLC**, **LCP**, 드라이브 | 설비의 직접적인 제어 및 연산 처리          |
| **Level 0**     | **Physical Process**    | 센서, 모터, 로봇 암           | 물리적 데이터(온도, 진동 등) 발생 및 동작 수행 |

### 데이터 수집의 핵심 흐름

1. **현장(Level 0-1)**: 센서가 데이터를 만들고 **PLC/LCP**가 이를 수집합니다.
2. **중간 집계(Level 2)**: 수집된 데이터는 로컬 네트워크상의 **게이트웨이**나 **SCADA**로 모입니다. 이때 보안을 위해 외부망과 분리된 **OT 네트워크**를 사용합니다.
   - *OT(Operational Technology)란?* 설비를 직접 제어하는 하드웨어/소프트웨어 전체를 가리키는 개념으로, 사무·경영 시스템을 뜻하는 IT(Information Technology)와 대비됩니다. OT 네트워크는 TCP/IP 프로토콜을 쓰더라도 인터넷과 물리적으로 차단된 폐쇄망(에어갭)으로 운영하는 것이 핵심입니다. 즉, OT의 본질은 특정 프로토콜이 아니라 **네트워크 격리**에 있습니다.
3. **상위 전송(Level 3-5)**: 정제된 데이터는 **MQTT, OPC-UA** 등을 타고 방화벽을 거쳐 **MES**나 **클라우드**로 올라가 분석됩니다. MES-ERP 간, 또는 클라우드 서비스 연동에는 **REST API**가 주로 쓰입니다(예: MES → ERP 생산 실적 전송, 외부 파트너사 데이터 교환).

이런 계층 구조 덕분에 현장의 기기들이 외부 공격으로부터 직접 노출되지 않으면서도, 필요한 데이터만 골라 상위 시스템으로 안전하게 보낼 수 있는 것입니다.

## 레벨 2와 3의 차이
레벨 2와 레벨 3은 공장의 **'현재 동작'**을 보느냐, 아니면 **'전체 실행 계획'**을 관리하느냐의 차이로 구분하면 이해가 빠릅니다.

### 레벨 2와 레벨 3의 주요 차이점

- **레벨 2 (현장 감시 및 제어):** 설비가 지금 잘 돌아가고 있는지 실시간으로 확인하는 단계입니다. SCADA나 HMI를 통해 모니터의 수치를 보며 밸브를 열거나 모터를 멈추는 등의 **직접적인 제어**가 일어납니다. 데이터의 단위가 '초'나 '밀리초'입니다.
- **레벨 3 (제조 운영 관리):** 현장에서 올라온 데이터를 모아 **생산 목표**와 비교하고 관리하는 단계입니다. "오늘 목표량 1,000개를 다 채웠나?", "불량률이 왜 높지?" 같은 분석과 작업 지시가 MES를 통해 이루어집니다. 데이터의 단위가 '분', '시간', '교대조' 단위로 길어집니다.

### 계층별 데이터 구조 및 통신 프로토콜 (업데이트)

아래로 갈수록 실시간성이 중요하고, 위로 갈수록 데이터의 통합과 분석이 중요해집니다.

| **계층 (Level)**  | **명칭**            | **주요 장치**      | **통신 프로토콜 (How)**                       | **역할 및 특징**                  |
| --------------- | ----------------- | -------------- | --------------------------------------- | ---------------------------- |
| **Level 4 & 5** | **Enterprise**    | ERP, Cloud     | **HTTP, REST API, MQTT, SQL**           | 전사 자원 관리, 빅데이터 분석, 경영 의사결정   |
| **Level 3**     | **Operations**    | **MES**, QMS   | **OPC-UA, MQTT, Ethernet/IP**           | 제조 실행 관리, 재고 및 품질 분석, 작업 지시  |
| **Level 2**     | **Control**       | **SCADA**, HMI | **Modbus TCP, PROFINET, EtherCAT**      | 공정 실시간 감시, 설비 간 데이터 통합 및 시각화 |
| **Level 1**     | **Field Control** | **PLC**, LCP   | **Fieldbus (Profibus, CANbus, Modbus)** | 설비 직접 제어, 로직 연산, 센서 데이터 수집   |
| **Level 0**     | **Physical**      | 센서, 액추에이터      | **I/O (4-20mA, Digital I/O), IO-Link**  | 물리적 신호 발생, 모터 구동, 온도/압력 측정   |

### 통신 방식의 변화 흐름

1. **하위 계층 (L0 ~ L1):** 전기적 신호나 매우 빠른 전용 통신(Fieldbus)을 사용하여 설비가 0.1초의 오차도 없이 움직이게 합니다.
2. **중간 계층 (L1 ~ L2):** 주로 산업용 이더넷(Industrial Ethernet)을 사용합니다. 일반 랜선과 비슷해 보이지만 진동이나 노이즈에 강하게 설계되어 있습니다.
3. **상위 계층 (L2 ~ L5):** 여기서부터 우리가 아는 **인터넷 표준 기술**이 본격적으로 쓰입니다. MES에서 분석한 데이터를 클라우드로 보낼 때는 보안이 강화된 MQTT나 REST API 방식을 주로 활용합니다.

## 주요 장치에 대한 물리적 실체 여부
물리적 장비(하드웨어)와 그 위에서 돌아가는 시스템(소프트웨어)을 구분해서 정리해 드릴게요.

### 1. 소프트웨어 vs 하드웨어 구분

| **구분**             | **명칭**              | **실체 (형태)**      | **역할 비유**     |
| ------------------ | ------------------- | ---------------- | ------------- |
| **소프트웨어 (System)** | **ERP, MES, SCADA** | 서버나 PC에 설치된 프로그램 | 두뇌, 관리자, 감시자  |
| **하드웨어 (Device)**  | **PLC, LCP, 센서**    | 전선이 연결된 기계 뭉치    | 신경계, 손발, 감각기관 |

- **SCADA/MES/ERP**: 이들은 눈에 보이는 기계라기보다, 컴퓨터(서버) 안에 설치되어 돌아가는 **프로그램**입니다. 물론 이 프로그램들을 돌리기 위한 '서버 컴퓨터'라는 물리적 장치는 존재하지만, 용어 자체는 시스템을 뜻합니다.
- **센서/LCP/PLC**: 이들은 공장 바닥에 실제로 고정되어 있고, 전선이 달려 있으며 손으로 만질 수 있는 **물리적 장치**입니다.

### 2. 실체가 있는 장비들에 대한 추가 설명

- **센서 (Sensor)**: 현장의 정보를 받아들이는 '코, 입, 귀'입니다. 온도를 재는 열전대, 물체의 유무를 판단하는 근접 센서, 압력을 재는 압력계 등이 있습니다.
- **LCP (Local Control Panel)**: 설비 바로 옆에 세워진 '철제 제어함'입니다. 현장 작업자가 직접 버튼을 누르거나 화면(HMI)을 터치해 기계를 조작할 수 있게 만든 물리적인 판넬입니다.
- **PLC (Programmable Logic Controller)**: LCP 안에 들어있는 '작은 컴퓨터'입니다. 일반 PC와 달리 공장의 거친 환경(먼지, 열)에서도 잘 견디도록 설계된 연산 장치입니다. 센서 신호를 받아 모터를 돌릴지 말지 결정합니다.
- **HMI (Human Machine Interface)**: LCP에 박혀 있는 '터치스크린'입니다. 기계의 상태를 그림으로 보여주고 사람이 조작할 수 있게 해주는 화면 장치입니다.
- **액추에이터 (Actuator)**: 전기 신호를 받아 실제로 움직임을 만드는 장치입니다. 모터, 실린더, 밸브 등이 여기에 해당하며 공장의 '근육' 역할을 합니다.

### 3. 왜 소프트웨어 이름들이 장치처럼 불릴까?

공장 사람들이 "SCADA에서 확인해 봐"라고 말할 때, 실제로는 **"SCADA 프로그램이 떠 있는 모니터 화면을 봐"**라는 뜻으로 쓰기 때문입니다.

- **SCADA**: 주로 제어실(Control Room)의 큰 모니터 화면들.
- **MES**: 현장 작업자들이 실적을 입력하는 키오스크나 태블릿 화면.
- **ERP**: 사무실 직원이 사용하는 PC 프로그램.
