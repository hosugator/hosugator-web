## 핵심 문제 구조

제조업 외관 검사(AOI)에서 AI 도입을 가로막는 구조적 문제:

1. 불량 샘플 희소성: 제조 현장은 정상 제품이 압도적 다수 → 지도 학습용 불량 데이터 수집 불가능
2. 미지 결함의 출현: 사전에 정의되지 않은 새로운 불량 유형은 지도 학습 모델이 탐지 불가
3. 다품종 전환: 제품 품종마다 표면 패턴이 달라 단일 모델 적용 시 성능 급락

→ 이 세 문제가 동시에 존재하기 때문에 단순 지도 학습 분류기는 초기 도입에 부적합.

---

## 단계별 전환 전략

```
초기 (정상 100~300장, 불량 없음)
    → 이상탐지 단독 (PatchCore)
    → "불량이다" 판정 가능, 유형 불명

        ↓ 불량 데이터 클래스당 200장+ 축적

중기 (라벨 확보)
    → 이상탐지 (1차 필터) + 분류기 (2차 유형 식별)
    → PatchCore가 불량 판정 → EfficientNet이 유형 분류

        ↓ 클래스당 500장+

장기 (안정 생산)
    → 지도 학습 강화 검토 가능
    → PatchCore는 "미지 결함 탐지망"으로 병행 유지 권장
```

핵심 비대칭: 지도 학습은 정확도가 높지만 학습 데이터에 없는 유형에 무력. PatchCore는 정확도가 낮지만 어떤 결함이든 이상을 감지. 두 모델은 대체 관계가 아닌 협력 관계.

## 다품종 대응 — 레시피별 모델 스왑 아키텍처

단일 모델로 다품종(두께·곡률·재질이 다른 제품) 처리는 성능 급락.  
현실적 구조: 품종(레시피)별 독립된 메모리 뱅크 또는 별도 모델 구성.  
품종 변경 시 해당 레시피의 모델로 스왑.

재학습 트리거:

| 조건 | 행동 |
|------|------|
| 품종 변경 | 해당 품종 메모리 뱅크 재구성 |
| 광학 환경 변경 (카메라·조명) | 전체 뱅크 재구성 필수 |
| 정기 갱신 | 새 양품 이미지 추가하여 보강 |

---

## 오픈소스 vs 상용 선택 기준

| 조건 | 선택 |
|------|------|
| 기술 내재화 목표, 장기 운용 | 오픈소스 (Anomalib) |
| 즉시 생산 라인 투입, AI 인력 없음 | 상용 (Cognex ViDi, MVTec HALCON) |

상용 솔루션은 초기 설정이 쉽지만 런타임 라이선스 비용이 지속 발생하며 내부 알고리즘 커스터마이징이 불가하다.

---

## 광학 환경 원칙

> 모델 성능보다 광학 환경 고정이 더 중요하다.

투명·반사 재질(렌즈, 금속)은 조명 각도·밝기·카메라 위치가 조금만 달라져도 정상 이미지가 불량으로 판정된다. 광학 환경이 바뀌면 기존 메모리 뱅크 전체가 무효화된다.
