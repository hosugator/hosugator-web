## 1. 지휘자(CPU)와 무대(메모리)의 관계

- 유일한 소통 창구: CPU가 직접 조작할 수 있는 물리적 세계는 오직 메모리뿐이다.
- 상주 원칙: 모든 데이터와 코드는 메모리에 올라와야만 CPU의 지휘권(실행 권한) 안에 들어온다.

## 2. 무대의 확장과 세분화: 트레이드 오프

### VRAM vs RAM: 대역폭과 지연 시간

메모리 설계에는 대역폭(너비)과 지연 시간(반응 속도) 사이의 선택이 존재한다.

| 구분  | 시스템 RAM (DDR)          | VRAM (GDDR)             |
| :-- | :--------------------- | :---------------------- |
| 특징  | 낮은 지연 시간 (Low Latency) | 높은 대역폭 (High Bandwidth) |
| 비유  | 민첩한 스포츠카 (빠른 반응)       | 거대한 화물 열차 (대량 수송)       |
| 용도  | CPU의 복잡하고 섬세한 로직 처리    | GPU의 단순하고 방대한 병렬 연산     |
| 한계  | 대량의 데이터 동시 처리 속도 낮음    | 첫 데이터 도착까지의 반응이 느림      |

### 메모리 활용 전략: Stack vs Heap

- Stack (스택): 함수 호출 시 사용하는 '손안의 도구함'. 지연 시간이 극도로 낮아야 하므로 CPU가 직접 관리한다.
- Heap (힙): 동적으로 사용하는 '거대 창고'. 공간은 넉넉하지만 관리 비용(할당/해제)이 발생한다.

## 3. 커널(Kernel): CPU의 특별한 상태

- 권한의 열쇠: 커널은 CPU가 '관리자 모드'일 때 실행하는 코드와 규칙 그 자체이다.
- 권한 수정: CPU가 커널 모드일 때만 메모리 지도를 수정하여, 특정 프로세스가 타인의 구역을 침범하지 못하도록 '칸'을 치는 작업을 수행한다.

## 4. 읽기(Read)와 쓰기(Write)의 권한 계층

- CPU (Architect): 커널 권한을 통해 메모리의 물리적 규칙을 설계한다.
- 작업자 (Performers): GPU, 프로세스, 스레드 등은 CPU가 허락한 메모리 주소(칸) 안에서만 데이터를 읽고 쓰며 움직인다.

## 5. 최종 통찰
> "CPU는 커널이라는 법전으로 메모리 무대를 설계하며, 빠른 반응이 필요한 곳(RAM)과 대량 수송이 필요한 곳(VRAM)을 전략적으로 배치하여 시스템이라는 거대한 교향곡을 완성한다."
