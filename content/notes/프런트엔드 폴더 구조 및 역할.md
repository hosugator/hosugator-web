#frontend #react-native #app #component #business-logic #global-context #routing
이 문서는 React Native 애플리케이션의 모범적인 폴더 구조와, 각 폴더에 담긴 UI, 기능 로직, 비즈니스 로직의 역할을 설명한다.
### 1. 뼈대: 라우팅 폴더 (`app/`)
`app` 폴더는 Expo Router의 파일 시스템 라우팅 규칙을 따른다. 각 폴더는 하나의 화면(페이지)을 의미하며, 그 안에 해당 페이지의 컨테이너 컴포넌트가 위치한다.
- `app/home/index.js`: `home` 페이지의 진입점. 하위 UI 컴포넌트를 불러와 기능 로직을 관리한다.
- `app/login/index.js`: `login` 페이지의 진입점. 로그인 폼 입력값 관리 등 기능 로직을 처리한다.
### 2. 재사용 가능한 UI 컴포넌트 (`components/`)
`components` 폴더는 여러 페이지에서 재사용할 수 있는 UI 컴포넌트들을 모아둔 곳이다. 이 컴포넌트들은 데이터를 props로 받아와 화면에 렌더링하는 역할만 담당한다.
- `components/HomeUI.js`: `app/home/index.js`가 사용하는 홈 화면의 UI 컴포넌트.
- `components/RestaurantCard.js`: `HomeUI.js`에서 사용하는 식당 카드 UI.
- `components/Button.js`: 버튼 컴포넌트 (예시).
### 3. 핵심 비즈니스 로직 (`services/`)
`services` 폴더는 애플리케이션의 핵심 비즈니스 로직을 담는 곳이다. 이 로직들은 UI와 완전히 독립적이며, 여러 컴포넌트에서 재사용될 수 있다.
- `services/authService.js`: 로그인, 회원가입 등 인증과 관련된 비즈니스 로직을 처리한다. (예: 서버 API 호출)
### 4. 전역 상태 관리 (`context/`)
`context` 폴더는 애플리케이션 전체에 걸쳐 공유되어야 하는 전역 상태를 관리한다.
- `context/AuthContext.js`: 사용자 인증 상태 (`isLoggedIn`, `user`)와 관련된 상태를 관리한다. `services/authService.js`의 결과를 받아 `AsyncStorage`에 저장하는 기능 로직도 포함될 수 있다.
### 5. 로직의 흐름 (예시: 로그인)
1. UI: 사용자가 로그인 페이지의 로그인 폼에 정보를 입력하고 로그인 버튼을 누른다. (`login/index.js`가 렌더링한 UI)
2. 기능 로직: `login/index.js`가 버튼 클릭 이벤트를 감지하고, 입력된 이메일과 비밀번호를 비즈니스 로직 함수(`authService.login()`)로 전달한다.
3. 비즈니스 로직: `authService.js`가 서버 API를 호출하여 인증을 요청하고, 성공 시 토큰을 받아온다.
4. 전역 상태: `AuthContext`는 토큰을 받아 `AsyncStorage`에 저장하고, 애플리케이션의 전역 로그인 상태를 업데이트한다.
5. 라우팅: `AuthContext`의 상태 변화에 따라 `expo-router`는 로그인 페이지에서 홈 페이지로 화면을 전환한다.
