## Context
학습된 모델을 추론에 사용하다가, 메모리를 사용하는 것과 모델 파일 그 자체의 차이는 무엇인지 원리가 궁금해졌다.
학습된 모델은 가중치 행렬의 집합이다.  메모리 안에서는 객체들의 참조 관계(포인터 그래프)로 존재하며, 이를 파일로 저장하려면 직렬화가 필요하다.

## Insights
### 모델 객체는 가중치 숫자만 갖고 있지 않다. 다음 레이어가 어디 있는지를 메모리 주소(포인터)로 가리킨다.

```
주소 0x1000: Layer1 { weights: [...], next: 0x2000 }
주소 0x2000: Layer2 { weights: [...], next: 0x3000 }
주소 0x3000: Layer3 { weights: [...], next: null  }
```

이 구조를 객체 그래프라고 한다 — 노드가 객체, 엣지가 포인터인 방향 그래프.

### 왜 파일로 그대로 저장할 수 없나
메모리 주소는 현재 실행 중인 프로세스 안에서만 유효하다.  
OS는 프로세스마다 독립된 가상 주소 공간을 부여하므로, `0x2000`을 파일에 적어두면 다른 프로세스에서 읽을 때 그 주소에는 전혀 다른 데이터가 있다.

```
프로세스 A의 0x2000 → Layer2 가중치
프로세스 B의 0x2000 → 관계없는 다른 데이터
```

### 직렬화는 포인터 기반 표현을 위치 독립적인 표현으로 변환한다
레이어의 논리적 순서는 존재한다. 다만 그 순서가 포인터 체인으로 표현되어 있는 것이 문제다.  

```
직렬화 전 (포인터 기반):
  Layer1.next = 0x2000  ← 주소에 의존

직렬화 후 (위치 독립):
  [layer_count=3][layer_0_weights...][layer_1_weights...][layer_2_weights...]
  ← 순서가 인덱스로 명시. 어디서 읽어도 동일하게 복원 가능
```

### 추론에는 RAM에 올리기 위한 전처리 작업으로 역직렬화가 필요하다

CPU의 연산 명령어는 RAM에 올라온 데이터에만 적용된다. 파일(디스크)은 직접 연산 대상이 될 수 없다.

| 저장소         | 접근 속도       |
| ----------- | ----------- |
| CPU 캐시 (L1) | ~1 ns       |
| RAM         | ~100 ns     |
| SSD         | ~100,000 ns |

SSD조차 RAM보다 1,000배 느리다. 추론 중 행렬 곱셈은 초당 수억 번의 메모리 접근이 일어나므로 디스크 속도로는 실시간 추론이 불가하다.

```
프로세스 시작 시 1회:
  파일 읽기 → 역직렬화 → RAM 상주

이후 추론은:
  RAM의 동일 객체 재사용 → 디스크 접근 없음
```

모델 객체 자체는 메모리에 상주하고, 각 추론에서 필요한 임시 버퍼만 생겼다 사라진다.
